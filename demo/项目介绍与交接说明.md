# 梧桐 Demo 项目介绍与交接说明

生成时间：2026-06-07

## 一、项目背景

梧桐 Demo 是一个面向内镜中心、疼痛医学科/麻醉相关科室的患者院前流程管理小程序原型。项目的核心问题是：患者在检查或无痛诊疗前，需要完成饮食、禁食禁饮、到院报到、注意事项、术前麻醉评估等一系列准备动作，但传统方式主要依赖人工口头告知、纸质材料、电话提醒和短信兜底，容易出现患者忘记、看不懂、漏填、到院后补流程等情况。

这个 Demo 的设计目标，是把患者院前准备流程做成一个可视化、可提醒、可追踪的小程序体验，让患者知道“现在该做什么、为什么要做、做完后下一步是什么”；同时让科室后台知道“哪些患者未完成关键节点、哪些患者未填写麻醉评估、是否需要人工或短信兜底”。

当前版本重点展示两条主线：

1. 患者端：检查准备流程、节点提醒、院前麻醉评估、评估报告、后续说明、我的信息。
2. 后台端：患者进度管理、麻醉评估推送管理、麻醉评估后台、数据统计、CSV 导出、触达记录示意。

## 二、Demo 目前能展示什么

### 1. 患者端小程序体验

- 首页展示当前检查人、下一步准备事项、流程进度。
- 流程页展示饮食注意、禁食禁水、到院报到、候诊、检查后说明等节点。
- 节点详情里展示“为什么要做”“具体步骤”“注意事项”。
- 底部导航包含：首页、流程、评估、后续、我的。
- “我的”页面在患者已完成评估后，会出现“麻醉评估报告”卡片。

### 2. 麻醉术前评估

- 患者端有明显的“院前麻醉评估”入口。
- 评估表包含：
  - 基本信息
  - 当前身体状况
  - 过往病史
  - 生活习惯
  - 手术及过敏史
  - 用药情况
  - 禁食禁饮情况
- 病史分类支持折叠展开。
- “以上情况都没有”有互斥保护逻辑，避免误覆盖患者已选择的风险项。
- 生活习惯中，直接点“以上情况都没有”会默认吸烟、饮酒均为“从不”。
- 禁食禁饮小时选择器中，点常用小时按钮会直接完成填写，不需要再点“确认选择”。
- 当填写进度达到 100% 时，会自动滚到页面底部，方便患者提交评估。
- 提交前有“麻醉术前评估知情确认”弹窗。
- 弹窗在手机上保持按钮首屏可见，正文必要时可滚动。
- 提交后用浏览器 localStorage 保存演示数据，并展示评估报告。

### 3. 后台管理体验

- 后台包含患者列表、流程进度、异常状态、麻醉评估状态。
- “麻醉评估推送管理”用于展示待填写、已完成、停止推送等状态。
- “麻醉评估后台”展示评估记录、风险摘要、每日评估、数据统计、数据管理。
- 支持导出 CSV，便于用 Excel/WPS 查看演示数据。

### 4. 触达与成本逻辑的展示

Demo 中已经体现了一个节省触达成本的思路：

- 优先通过小程序/微信订阅消息提醒患者填写评估。
- 如果患者已填写，后续同类评估提醒自动停止。
- 如果患者未填写，再通过短信兜底或人工处理。

目前这些是静态演示逻辑，还没有真正接入微信订阅消息、短信平台或医院系统。

## 三、项目当前技术结构

当前 Demo 是一个 Vite + React + TypeScript 静态前端项目，适合部署到 GitHub Pages 这类静态网页平台。

主要目录：

- `src/App.tsx`：患者端、后台端、路由和主要演示页面。
- `src/components/AnesthesiaAssessment.tsx`：麻醉评估表单核心页面。
- `src/components/assessment-summary.tsx`：麻醉评估报告展示。
- `src/components/assessment-ui.tsx`：评估表单通用 UI 组件。
- `src/lib/assessment.ts`：评估数据结构、BMI、ASA、风险摘要、记录标准化等业务逻辑。
- `src/index.css`：整体样式、患者端、后台端、评估表、报告、弹窗等样式。
- `scripts/verify-anesthesia-demo.mjs`：Demo 功能完整性检查脚本。
- `dist/`：已经构建好的静态网页产物。

## 六、当前边界和未完成事项

这个版本适合做 Demo 演示、科室主任/护士长沟通、合作程序员交接，但还不是可直接上线到医院生产环境的系统。

当前未接入：

- 真实微信小程序账号
- 微信订阅消息接口
- 短信平台
- 医院 HIS/预约系统/叫号系统
- 真实数据库
- 登录鉴权和权限系统
- 医疗数据合规存储
- 正式服务器和运维监控

当前数据保存方式：

- 患者提交评估后，数据保存在浏览器 `localStorage` 中。
- 后台读取的是静态演示数据和本地浏览器演示数据。
- 换浏览器、清缓存或换设备后，演示数据可能不存在。

## 七、建议下一步

如果继续推进到可落地版本，建议按下面顺序做：

1. 明确第一期只服务哪一种检查流程，例如无痛胃肠镜。
2. 确定患者真实入口：微信小程序、公众号菜单、短信链接或院内二维码。
3. 接入真实后端数据库，保存患者流程状态和麻醉评估记录。
4. 接入微信订阅消息，并设计“未读/未填写/已填写”的触达策略。
5. 接入短信兜底，只给关键节点或未响应患者发短信。
6. 后台增加角色权限：护士、医生、管理员。
7. 对麻醉评估内容做医生审核，形成正式医疗文案。
8. 做试点科室小范围内测，再根据患者和护士反馈迭代。

## 八、给合作程序员的交接重点

这个 Demo 的重点不是炫技，而是验证业务流程是否成立：

- 患者能不能按节点完成准备？
- 患者会不会漏填麻醉评估？
- 填完后护士能不能在后台看到？
- 填完后是否能停止无意义触达，节省短信成本？
- 到院后是否能减少补问、补填、解释成本？

代码层面建议优先看：

1. `src/lib/assessment.ts`
2. `src/components/AnesthesiaAssessment.tsx`
3. `src/components/assessment-summary.tsx`
4. `src/App.tsx`
5. `scripts/verify-anesthesia-demo.mjs`

如果要改评估逻辑，优先改 `src/lib/assessment.ts`；如果要改患者填写体验，优先改 `AnesthesiaAssessment.tsx`；如果要改首页、我的、后台，优先改 `App.tsx`。
