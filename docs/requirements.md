# wutong 需求整理

## 项目基础信息

| 项目 | 内容 |
|---|---|
| 项目名 | wutong |
| 业务全称 | 无痛胃肠镜全流程智能导诊微信小程序 |
| 当前阶段 | 第一版跑通 MVP |
| 目标平台 | Coze/Codex 原型开发，后续发布为微信小程序 |
| 试点范围 | 单个内镜科室 |
| 年接诊量 | 1.66 万例 |
| 高峰接诊 | 工作日 60 例/天，周六 30 例/半天 |

## 核心定位

系统完全独立运行，不对接医院 HIS、预约、报告等系统。第一版只解决三个核心痛点：

1. 患者记不住服药和禁食禁水时间。
2. 患者找不到科室位置。
3. 患者不清楚下一步流程。

## 用户角色

| 角色 | 权限 |
|---|---|
| 患者端用户 | 普通微信用户，扫码进入，无需注册，无需复杂信息 |
| 医护管理员 | 科室护士/医生，账号密码登录，拥有全部管理、配置、消息推送权限 |

第一版不做多级权限。

## 患者端功能

| 模块 | 要求 |
|---|---|
| 入口表单 | 检查日期、检查时段、是否无痛、姓名、联系电话必填；基础病史选填折叠展示 |
| 自动时间线 | 根据上午/下午固定规则生成个性化节点 |
| 时间线主页 | 展示患者信息、禁食禁水提醒、节点状态、当前下一步 |
| 节点详情 | 操作步骤、禁忌注意、宣教图片/短视频占位、院内节点路线信息 |
| 自动提醒 | 每个节点提前 1 小时推送微信订阅消息；当前原型为提醒计划和模拟 |
| 到院流程 | 点击“我已到院报到”后切换为院内流程 |
| 院内节点 | 报到核对、穿刺室、候诊区、检查室、术后复苏、离院 |
| 术后页面 | 饮食、活动禁忌、异常处理、取报告、复诊提醒 |

## 居家时间规则

| 检查时段 | 节点 |
|---|---|
| 上午 | 检查前 1 天 20:00 第一次服泻药；检查当天 02:00 严格禁食禁水；检查当天 04:00 第二次服泻药+祛泡剂；检查当天 07:30 到院报到 |
| 下午 | 检查前 1 天 20:00 第一次服泻药；检查当天 07:00 严格禁食禁水；检查当天 08:00 第二次服泻药+祛泡剂；检查当天 12:30 到院报到 |

说明：需求原文列举了上午 04:00 第二次服药和检查前 6 小时禁食禁水；实际时间线按时间顺序展示，因此上午禁食禁水显示在 02:00。

## 医护后台功能

| 模块 | 要求 |
|---|---|
| 登录 | 单管理员账号密码登录，支持改密码 |
| 患者总览 | 列表、日期筛选、进度筛选、姓名/电话搜索 |
| 进度管理 | 查看患者流程、手动调整检查时间和节点进度 |
| 消息管理 | 单人/批量发送微信提醒；当前原型为模拟发送 |
| 内容配置 | 修改居家/院内节点时间、文案、操作说明、图片/视频、路线 |
| 数据统计 | 每日/月检查人数、节点完成率、CSV 导出 |

## 严禁超出 MVP 的功能

- AI 智能答疑
- 清肠效果自评
- 家属同步提醒
- 短信/电话提醒
- 医院 HIS、预约、挂号、报告系统对接
- 第三方平台对接
- 多级权限
- 复杂质控报表
- 长期随访系统
- 支付、挂号、在线问诊、报告查询

## 合规边界

当前原型只能用于流程验证，不能直接承载真实医疗生产数据。正式上线必须实现服务端加密存储、HTTPS、管理员访问控制、审计日志、备份恢复、数据保留策略和微信订阅消息真实授权/发送。
