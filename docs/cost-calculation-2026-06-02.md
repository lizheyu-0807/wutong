# wutong 成本详细核算

生成日期：2026-06-02  
项目：无痛胃肠镜全流程智能导诊微信小程序  
核算范围：当前 GitHub Pages 演示版、单科室微信小程序试点版、医院正式上线增强版  

## 1. 先说结论

这件事能做，而且当前接诊量不需要大服务器。真正花钱的地方不是算力，而是微信小程序正式上线、数据安全、备份、审计、合规和后续运维。

最中肯的结论：

| 场景 | 建议预算 | 是否适合真实患者数据 | 判断 |
|---|---:|---|---|
| 当前 GitHub Pages 演示版 | 0 元/年 | 不适合 | 只能手机预览和演示流程 |
| 极简微信小程序试跑版 | 500-1,500 元/年 | 不建议 | 可做内部演示，不建议承载真实医疗数据 |
| 单科室正式试点推荐版 | 4,000-8,000 元/年云资源 | 可以，但要补齐安全措施 | 最适合第一版上线试点 |
| 医院合规增强版 | 15,000-50,000 元/年 | 更适合 | 适合医院信息科要求较严的场景 |
| 如果包含一次性开发改造 | 30,000-120,000 元一次性 | 取决于改造质量 | 当前原型不能直接当生产系统 |

我不建议为了省钱直接把当前 GitHub Pages 页面给患者使用。原因很简单：它没有服务端、没有真实微信订阅消息、没有管理员权限隔离、没有医疗数据加密存储、没有审计日志，患者填写的数据只在浏览器本地保存。

## 2. 核算依据

### 2.2 请求量估算

第一版没有 AI 问答、没有报告查询、没有医院系统对接，请求量很低。

我按每名患者 50-90 次系统请求估算，包含：

| 行为 | 单人请求估算 |
|---|---:|
| 建档/保存检查信息 | 2-5 次 |
| 查看时间线 | 5-10 次 |
| 查看节点详情 | 8-15 次 |
| 点击完成节点 | 8-15 次 |
| 到院流程切换 | 2-5 次 |
| 医护后台查看和调整 | 10-20 次 |
| 提醒计划和发送记录 | 10-20 次 |
| 合计 | 50-90 次/人 |

计算结果：

| 项目 | 低估 | 高估 |
|---|---:|---:|
| 年请求量 | 830,000 次/年 | 1,494,000 次/年 |
| 月请求量 | 约 69,167 次/月 | 约 124,500 次/月 |
| 60 人高峰日请求量 | 3,000 次/天 | 5,400 次/天 |
| 如果集中在 2 小时内 | 0.42 次/秒 | 0.75 次/秒 |
| 再乘 10 倍安全冗余 | 4.2 次/秒 | 7.5 次/秒 |

结论：这个量级很小。2 核 4G 或 CloudBase 标准版已经足够。上 4 核 8G不是因为性能不够，而是为了更稳、更好满足医院合规和运维要求。

## 3. 存储量估算

### 3.1 结构化数据

每名患者数据包括姓名、电话、检查时间、节点状态、提醒记录、管理员操作记录。保守按 100KB/人/年估算。

| 项目 | 计算 | 结果 |
|---|---:|---:|
| 患者结构化数据 | 16,600 人 * 100KB | 约 1.66GB/年 |
| 审计日志和访问日志 | 按患者数据 2-5 倍 | 3-8GB/年 |
| 数据库索引和冗余 | 按 30%-100% | 2-10GB/年 |
| 合计建议预留 | - | 20GB/年起步 |

结论：数据库不是成本大头。正式试点按 50-100GB 数据库存储买就足够，主要是留出日志、备份和增长空间。

### 3.2 图片和视频素材

科室路线照片、宣教图、短视频会占用对象存储。

| 素材规模 | 假设 | 建议对象存储 |
|---|---|---:|
| 极简图文版 | 科室照片、流程图、少量宣教图 | 10-20GB |
| 普通宣教版 | 多节点图片 + 少量短视频 | 50-100GB |
| 视频较多版 | 多条宣教视频、不同检查类型素材 | 100-300GB |

建议第一版控制在 100GB 内。视频尽量压缩，不要直接上传原始大文件。

## 5. 方案 A：极简微信小程序试跑版

适合：给科室内部、院内管理层或信息科看流程，不承载真实患者数据。

推荐组合：

| 成本项 | 规格 | 月费用 | 年费用 |
|---|---|---:|---:|
| 微信小程序认证 | 预算按常见企业主体认证口径 | - | 300 元 |
| CloudBase 个人版 | 19.9 元/月 | 19.9 元 | 238.8 元 |
| 对象存储 | 10-20GB，少量图片 | 约 2-5 元 | 约 24-60 元 |
| 域名 | 可不用，使用云开发默认域名/小程序环境 | 0 元 | 0 元 |
| 备份/审计 | 只做最低限度 | 0-50 元 | 0-600 元 |
| 合计 | - | 约 22-75 元 | 约 563-1,199 元 |

判断：能演示，但不建议承载真实患者数据。个人版成本低，不过医院试点不应只看价格，因为自动暂停、备份、审计和权限管理才是关键。

## 7. 方案 C：自建服务端增强版

适合：医院信息科不希望完全依赖云开发，要求独立后端、独立数据库、更强运维控制。

推荐组合：轻量应用服务器 + 轻量数据库/云数据库 + COS + CDN + 日志备份。

| 成本项 | 推荐规格 | 月费用 | 年费用 |
|---|---|---:|---:|
| 微信小程序认证 | 企业/机构主体认证预算 | - | 300 元 |
| 轻量应用服务器 | 2核4G、约 100GB、7Mbps、1000GB/月流量 | 90 元 | 1,080 元 |
| 轻量数据库服务 | 2核4G、120GB SSD | 198 元 | 2,376 元 |
| 对象存储 COS | 100GB 标准存储 | 11.8 元 | 141.6 元 |
| CDN 流量包 | 500GB/12个月流量包参考 | - | 228 元 |
| 日志与监控 | 云日志、告警、错误追踪 | 100-300 元 | 1,200-3,600 元 |
| 备份与快照 | 数据库备份、服务器快照、对象存储备份 | 100-300 元 | 1,200-3,600 元 |
| 域名 | .com/.cn 普通域名 | - | 50-100 元 |
| 合计 | 不含开发人力 | 约 500-900 元 | 6,576-10,626 元 |

判断：比 CloudBase 标准版更可控，但维护复杂度更高。除非医院明确要求独立服务端，否则第一版不必一开始就走这条路。

## 8. 方案 D：医院合规增强版

适合：信息科、安全科要求较严，涉及真实患者信息，要求审计、备份、最小权限、数据加密、应急恢复。

| 成本项 | 建议预算 |
|---|---:|
| 云资源基础成本 | 8,000-15,000 元/年 |
| 日志审计和安全告警 | 3,000-10,000 元/年 |
| 备份、快照、容灾演练 | 3,000-10,000 元/年 |
| 渗透测试/安全扫描 | 5,000-30,000 元/次 |
| 等保/院内安全评估配合 | 视医院要求，可能 10,000 元以上 |
| 年度合计 | 15,000-50,000 元/年起 |

判断：这不是服务器变贵，而是合规要求变贵。医疗场景里，真实成本往往花在“出了问题能不能追责、恢复、证明合规”。

## 9. 一次性开发改造成本

当前项目是 MVP 原型，不是生产级微信小程序。若要真正上线，需要从静态原型改成小程序 + 服务端。

| 工作项 | 低配预算 | 稳妥预算 | 说明 |
|---|---:|---:|---|
| 微信小程序端改造 | 8,000-20,000 元 | 20,000-50,000 元 | 页面、表单、时间线、订阅消息授权 |
| 后端接口和数据库 | 10,000-30,000 元 | 30,000-80,000 元 | 患者、节点、提醒、后台配置 |
| 医护后台生产化 | 8,000-25,000 元 | 20,000-60,000 元 | 登录、筛选、导出、配置、审计 |
| 安全加固 | 5,000-20,000 元 | 20,000-80,000 元 | 加密、权限、日志、备份、脱敏 |
| 测试和上线 | 5,000-15,000 元 | 15,000-40,000 元 | 真机、兼容、审核、试运行 |
| 合计 | 30,000-90,000 元 | 80,000-300,000 元 | 取决于医院验收要求 |

中肯判断：如果只是单科室试点，30,000-90,000 元的一次性改造比较现实；如果要按医院正式信息化项目验收，80,000 元以下往往会很紧。

## 11. 不能省的钱

| 项目 | 为什么不能省 |
|---|---|
| 数据库备份 | 医疗数据误删后必须能恢复 |
| 操作审计 | 谁改了患者流程、谁导出了数据，需要可追踪 |
| HTTPS | 小程序服务域名和患者数据传输都需要 |
| 管理员权限控制 | 不能所有人共用一个弱密码 |
| 订阅消息授权流程 | 不授权就不能可靠提醒患者 |
| 隐私政策和用户告知 | 患者姓名、手机号、检查信息都属于敏感信息 |
| 数据脱敏导出 | Excel 导出最容易泄露患者信息 |

## 13. 最终建议

如果只是明天用手机看：现在 0 元的 GitHub Pages 已够用。

如果要给科室内部演示：准备 800-4,200 元/年预算即可，但只能测试，不要上真实患者数据。

如果要做单科室真实试点：建议按 10,000-30,000 元/年做预算，其中云资源只是 4,000-8,000 元，剩下的钱用于备份、审计、安全、运维和问题处理。

如果医院要求正式信息化项目验收：不要按“几千元小程序”去报。更现实的口径是一次性开发改造 80,000-300,000 元，年度运行维护 15,000-50,000 元。
